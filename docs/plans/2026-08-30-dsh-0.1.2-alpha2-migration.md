## 迁移步骤

> 顺序要点：**先**完成 dsh 源码升级（含 install+build），**再**重建插件 lib/ —— 插件的 typecheck/build 经 `link:` 直接消费 source/current 的 alpha2 源码与产物。

1. **升级 dsh 运行源码（人类执行，插件目录之外）**：按 `~/.dsh/source/current` 的 SOP 执行 `git pull --ff-only` → `pnpm install --prefer-offline` → `pnpm run build`（前台长 timeout），并验证 `apps/cli/lib/bin.js` 与 `packages/bundle/web-app/lib/index.js` 存在。alpha.2 新增 4 个 workspace 包，**跳过 install 会直接导致插件 typecheck 报 `Cannot find package`**。
2. **插件源码改动：无需改动。** 逐项核查结论：`connectionGeneration→hostInfo` 不涉及；session 事件不消费；`settings.section`、locale、conversation、ui-primitives、dsh-tools、webServer、sessions/agents/loader 服务键全部原样。`src/context-types.ts` 的结构化镜像与 `src/types.d.ts` 的 ambient 声明与 alpha2 实测形状一致，无需更新。
3. **（可选，hygiene）对齐 peerDependencies**：`package.json` 中 9 个 `@deepseek-ai/dsh-*` peer 由 `^0.0.1` 改为 `^0.1.2-alpha.2`（`@deepkeep-ai/cordis ^4.0.1` 保持即可，4.0.2 已满足）。此改动纯声明性质（peers 均 optional），**不做也不阻塞升级**；若做，属 package.json 一行级改动，仍须遵守「本机 `link:` 路径补丁不提交上游」的既有纪律。
4. **重建 lib/**（插件目录内，幂等）：
   ```powershell
   Push-Location D:/Projects/deepseek-harness/dsh-aigc-canvas
   pnpm run typecheck   # 对照 alpha2 类型（link: 已指向 source/current）
   pnpm test            # vitest run（canvas-registry / tools / wire）
   pnpm run build       # tsdown → lib/index.js + lib/invariant.js + lib/client.js；tsc 产 d.ts
   Pop-Location
   ```
   无需改任何构建配置：`tsdown.config.ts` 的 CLIENT_EXTERNALS（react/cordis/ui-primitives/ui-slots 及 `/client` 子路径）与 alpha2 `PLATFORM_MODULES` 逐项对齐（该清单两版零差异），client bundle 的 `window.__ModuleLoader__.load({id, factory})` 契约未变。
5. **profile 端生效：无需重装。** profile 以 `link:` 引用本插件（`~/.dsh/profiles/web/package.json:6`，SymbolicLink 已确认）——`lib/` 重建后 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-aigc-canvas/lib/` 即时可见；**禁止**对 link 引用跑 `dsh plugin --profile web update`（无效操作）。无需改动 `cordis.patch.yml`（insert 行结构与 alpha2 无关）。
6. **对外发布（可选，走 huanlinoto 发布 SOP）**：`pnpm run build` → `npm pack --dry-run` 核对 files（`lib/` + `assets/` + `cordis.patch.yml`）→ `pnpm publish`（`publishConfig.access: public` 已声明）；`github:` 引用的部署则在 build 后 `git add lib/ && git commit && git push`，再 `dsh plugin --profile web update @huanlin/dsh-plugin-aigc-canvas`。**全程不需要改 `dsh/` 任何文件（零源码 patch 保持）**。
7. **重启 `dsh web` 进程 + 浏览器硬刷新（Ctrl+Shift+R）**（由人类执行）。

## 升级后验证清单

> 以下全部在 **dsh web 重启 + Ctrl+Shift+R 之后** 进行；启动应由人类执行 `dsh web`。

1. **加载面**：WebUI 启动无 `Failed to load plugins` / 无指向 `@huanlin/dsh-plugin-aigc-canvas` 的 `Cannot find package` 或 module table 报错（client bundle id `@huanlin/dsh-plugin-aigc-canvas` 经 `window.__ModuleLoader__.load` 注册成功）。
2. **工具注册**：新会话中模型工具列表可见全部 `aigc_*` 工具（get_provider_info / http_request / provider_set_instructions / canvas_place / canvas_link / canvas_unlink / canvas_list_elements 及 media_edit 族）——验证 `ctx.tools.register` 与 dsh-tools 契约在 alpha2 下完好。
3. **Stub 生成链路**：让模型调用 `aigc_get_provider_info`（应列出 stub provider）→ `aigc_http_request` 生成一张图 → `aigc_canvas_place`：验证 `defineTool` 执行、`exec.agent.session.id` 会话绑定、文件落盘 `<cwd>/.dsh-aigc-canvas/<sessionId>/`。
4. **画布视图（better-sidebar 存在时）**：打开 `aigc-canvas:main` tab：节点按 kind 着色、SVG 连线（promise→输出多对一）、双击节点显示 prompt/params；确认 WS `/aigc-canvas/ws/canvas` 推送正常（DevTools Network → WS 帧）。
5. **设置页**：Settings → AIGC Canvas（settings.section 槽）：provider 增删改可保存、`initialize` 动作能向当前会话发送 prompt（`conversation.send` 在 alpha2 ui-conversation 重构后仍工作）、文案跟随语言切换（locale 契约）。
6. **上下文注入通知**：在画布删除一个元素 / 拖拽上传一个文件 → 下一条模型消息应收到对应 notice（验证 `ctx.agents.get().inject()` 与 `source: {kind:'plugin'}` 形状在 alpha2 无回归）。
7. **媒体路由与围栏**：节点媒体可加载（`/aigc-canvas/file`），`download=1` 可下载；从非信任 Host 访问 API 应 403（trust-fence + alpha2 web-app 仍派发 trustedHosts）。
8. **持久化水合**：刷新浏览器与重启 `dsh web` 各一次，画布应从 `canvas.json` 完整恢复（元素 + 位置 + 边），媒体不丢——覆盖 alpha2 session probe/stat 行为变化的最直接回归面。
9. **WS 断线恢复**：DevTools 断网 ≥2s 再恢复 → 画布自动重连并拉到最新快照（client `store.ts` 自带 2s 重连；与上游 web 端新增的连接恢复指示器互不干扰）。
