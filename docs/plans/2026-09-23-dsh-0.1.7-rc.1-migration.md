## 行动

1. **RC1-01 peer 提升**：9 个 `@deepseek-ai/dsh-*` peer `^0.1.5-rc.1` → `^0.1.7-rc.1`（`cordis:^4.0.0-rc.7` 按任务保持不动）。
2. **RC1-15 核验**：`dsh.bundle.patch = "./cordis.patch.yml"` 仍合法；`dsh.client.inject` 6 个包均未改名；无被删字段。
3. **schemastery 依赖切换**（见「额外发现」）：`dependencies` 的 `schemastery@^3.18.0` → `@deepseek-ai/schemastery@^3.18.4`；`src/config.ts:9` import 同步。host 半仍内联（`tsdown.config.ts` hostConfig 无 external）。
4. **ambient 类型**：`src/types.d.ts` 的 `@deepseek-ai/dsh-tools`（`defineTool`/`ToolRunContext`/schema）与 `cordis`（`tools`/`webServer`/`sessions`/`agents`/`loader`/`effect`/`on`/`inject`/`provide`）形状经 rc.1 类型源逐项核对**无需改动**（`ToolOutputDefinition.presentationMeta?`、`ToolRunContext.{signal,callId,name,arguments,agent?}` 等均保留）。

## 额外发现（无对应卡，primary source 支撑）

1. **schemastery 类型冲突（已修）**：rc.1 vendor schemastery 升 `@deepseek-ai/schemastery@3.18.4`（新增 `SchemaMode`/`Volatile`、`Schema` 变 3 泛型），与插件原用的普通 `schemastery@3.18.0` 在 tsc program 内合并 `declare global { namespace Schemastery }`，使 `src/config.ts:79 export const Config: z<AigcCanvasConfig> = z.object({...})` 报 TS2322（`providers` 数组默认值触发 `Volatile`）。按 `plugin-development-guide.md` 红线清单改用 `@deepseek-ai/schemastery`。**该报错经任务规定的「registry devDep 临时替换」配方复现确认**。
2. **`Message.source.kind: 'plugin'` 移除（未改，pending）**：`src/index.ts:110-120` `notifyAgent` 构造 `{ role:'user', source:{ kind:'plugin', plugin:'dsh-aigc-canvas', form:'notice', summary } }`。rc.1 `@deepseek-ai/dsh-llm` 的 `MessageSourceMap` 去掉了共用 `plugin` kind（rc.1 `message.d.ts`：“there is no shared catch-all `plugin` kind”），改为各生产者自行 module-augment。本插件用**结构性** `AigcUserMessage`/`AigcAgent`（`src/context-types.ts`）且不经手 `Message` 联合类型，故 typecheck 不受影响；rc.1 转录渲染按 `form`（`ContextBody.d.ts` notices 由 `form` 投影）而非 `kind`，`form:'notice'` 仍在，故运行时表现保持。未改动以遵循最小改动；若后续上游按 kind 校验或要类型精确，应 module-augment `MessageSourceMap` 声明自有 kind。
