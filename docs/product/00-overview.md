# dsh-aigc-canvas 产品规划总览

> 本目录是 dsh-aigc-canvas 插件的产品改进规划文档，面向 PM / 设计 / 开发协作。
> 技术实现细节见各文档末尾「实现要点」一节，但主体描述保持在「用户/Agent 实际看到和能做什么」层面。

---

## 一、现状定位

**当前定位**：provider-agnostic 的 AIGC HTTP 桥 + 自由画布 + ffmpeg 后处理。

**已有亮点**：
- Agent 自己探测 API 并持久化"调用说明"（`aigc_provider_set_instructions`）
- `$base64` / `$data_uri` 占位符让 Agent 不用自己编码二进制
- stub 后端的路径分类让 dry-run 接近真实
- 元素 filePath 作为主标识符，不把 uuid 暴露给模型
- `notifyAgent` 机制让用户删除/拖拽时 Agent 不会引用已不存在的元素
- 多列自动布局 + 参考元素右侧定位

**核心诊断**：画布目前是"**结果陈列馆**"而非"**Agent 工作台**"——它展示 Agent 做了什么，但不帮 Agent 决定下一步做什么。

---

## 二、定位转变

| | 现在 | 改进后 |
|---|---|---|
| **画布对 Agent** | 看到自己做了什么 | 据此决定下一步做什么 |
| **画布对用户** | 浏览产物 | 干预、对比、迭代、复用 |
| **抽象层级** | 单次生成（原子操作） | 复合目标（工作流） |
| **Agent 行为模式** | 失败从头来 | 基于画布状态推理 + 重做/变体 |
| **跨会话** | 会话一关即孤立 | 资产可沉淀、可复用 |

## 三、四大改进方向

### 方向 A：Agent 自主性 ⚠️ 最弱项

让 Agent 从"会调 API"升级到"会基于已有产物推理下一步"。

**核心改进**：
1. 语义化边——连线带标签（首帧/尾帧/风格/变体/编辑自等）
2. 元素记录"我是怎么来的"——host 自动存原始请求
3. 重新生成（reroll）——失败重做 1 步完成
4. 批量变体——"给我 4 个选项"原生支持
5. 元素生命周期——草稿/就绪/否决/归档分层

详见：[01-agent-autonomy.md](./01-agent-autonomy.md)

### 方向 B：工作流能力 ⭐ 最大跃迁机会

让插件从"调 API 的工具集"升级到"完成 AIGC 任务的工作环境"。

**核心改进**：
1. Pipeline DAG——声明式提交多步任务，host 拓扑排序 + 并行 + 进度通知
2. 断点续跑——中间失败保留产物，从断点继续
3. Pipeline 模板——复合目标一键复用
4. 异步 + 进度面板

详见：[02-pipeline.md](./02-pipeline.md)

### 方向 C：Provider 知识结构化 ⚠️ 多 provider 阶段必做

**核心改进**：
1. Endpoint Catalog——把 `instructions: string` 升级为结构化能力表
2. Provider 选择策略——按 capability 分组、按优先级排序
3. 半自动探测——Agent 探测后填出结构化 catalog，不是模糊的自然语言
4. 按需拉详情——`aigc_get_provider_info` 默认精简视图

详见：[03-provider-catalog.md](./03-provider-catalog.md)

### 方向 D：UX 与可靠性

**核心改进**：
1. 右键菜单丰富（重新生成 / 用作参考 / 发到对话 / 下载 / 提升到资产库 / 标 winner）
2. 对比视图——多选元素同尺度并排挑 winner
3. 请求日志面板——调试失败生成刚需
4. 自动重试 + 去重——省 provider 成本
5. 成本追踪——画布 header 显示本会话总花费

详见：[04-ux-reliability.md](./04-ux-reliability.md)

## 四、发布前必修

这些不是产品改进，是发布到 dsh-external 之前必须做的卫生工作：

1. **README 严重过期**：还在描述旧的 5 工具架构（`aigc_text_to_image` 等），实际代码是 8 工具 provider-agnostic 架构
2. **`media-edit.ts` 硬编码 `D:\Softwares\ffmpeg\bin\ffmpeg.exe`**：开发者本机路径，别人机器上必坏
3. **`instructions` 200 字硬上限**：多能力 provider 装不下，会逼 Agent 写过度压缩到失真的说明

详见：[05-pre-release-fixes.md](./05-pre-release-fixes.md)

## 六、核心场景前后对比

### 场景：失败重做

**现在**：用户说"这张姿势不对，重画一张" → Agent 列画布 → 读 meta（格式不保证）→ 自己拼请求 → 调 API → 摆画布。4 步操作，慢且容易出错。

**改进后**：用户说"这张姿势不对，重画一张，姿势改成坐着" → Agent 调"重新生成"工具，传入原图 + "姿势改成坐着"。1 步完成。新图自动以"变体"关系连到原图。

### 场景：给用户多个选项

**现在**：用户说"给我 4 张不同姿势的猫" → Agent 串行调 4 次 API，自己算坐标，4 次摆画布。用户等很久，布局乱。

**改进后**：用户说"给我 4 张不同姿势的猫" → Agent 调一次"批量变体"工具，host 并行调用，4 张图自动 2×2 网格摆放，全部以"变体"关系连到一个虚的"簇"节点。用户在画布上直接看到 4 张并排，可多选 → "对比" → 选 winner，其他自动归档。

### 场景：复合目标

**现在**：用户说"做个 30 秒产品广告片" → Agent 自己拆解成"生图 → 生视频 → 配音 → 合成 → 剪辑"，每步独立调工具，串行等待，中间出错从头重来。

**改进后**：用户说"做个 30 秒产品广告片" → Agent 调用"工作流"工具，提交一份步骤清单。host 拓扑排序、能并行的并行、每步完成主动通知 Agent 进度。画布上：每步产物自动入图、自动按关系连边。如果第 3 步失败：前 2 步的产物保留，Agent 从断点续跑。

### 场景：Agent 理解画布状态

**现在**：Agent 调"列出画布"工具，只能看到"这俩元素有连线"，但不知道连线是什么意思。

**改进后**：Agent 调"列出画布"工具，看到的是带语义的关系图：
```
prompt A →[首帧]→ video B
prompt C →[尾帧]→ video B
prompt D →[输入]→ video B
```
Agent 能据此推理："B 是用 A 做首帧、C 做尾帧生成的，如果 B 的开头不好，我可以重新生成首帧 A"。
